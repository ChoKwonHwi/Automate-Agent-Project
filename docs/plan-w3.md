### 1~2. 인용문 대조 거절 + 거절 규칙 재조정 (Qwen3 8B, 33문항)

| 지표 | W2 (v2) | W3-1 인용문 대조 | **W3-2 규칙 재조정** | W3 목표 |
|---|---|---|---|---|
| 거절 정확도 (refuse 4) | 50% | 100% | **100%** | ≥ 80% |
| 오거절률 | 3% | 21% | **14%** | ≤ 5% |
| └ 검증 단계 거절 (원래 틀린 답) | - | 2 | 2 | |
| └ LLM 스스로 거절 | 1 | 4 | 2 | |
| 인용 적중 | 86% | 96% | **96%** | ≥ 90% |
| 근거 밖 조항 인용 (문항) | 2 | 0 | 1 | 0 |
| 생성 지연 p95 | 4.3s | 8.6s | 10.4s | ≤ 10s |

리포트: [W3-1](../eval/reports/w3_1_quote_verify.md) · [W3-2](../eval/reports/w3_2_refusal_rule.md)

**방법** — 모델 출력에 `quotes`(근거 원문 그대로 복사한 문장)를 먼저 쓰게 하고(`ANSWER_SCHEMA` 필드 순서), 코드가 대조한다.
- 인용문이 근거 원문에 있는가 — 공백 · 표 구분자 · 가운뎃점 차이는 무시, 그 외 차이는 일치 위치 주변 창과 85% 이상 일치해야 인정
- 답에 나온 기한 · 기간(일 · 개월 · 년 · 근무시간)이 검증된 인용문에 있는가 — 금액 계산값은 W4 계산 도구 몫이라 제외
- 둘 중 하나라도 실패하면 답하지 않는다 (`refused_by="verification"`, 거절 전 답은 `raw_answer` 로 보관)

**결과 해석**
- 거절 50% → 100%: q003 의 "8근무시간 이내" 같은 지어낸 기한이 인용문 대조에서 걸린다.
- 검증 단계 거절 2건(q024 강사료 80,000원, q031 "3년 지나면 선발 가능")은 **원래 틀린 답**이었다 — 틀린 답 대신 거절 (안전한 실패).
- 인용문 대조 도입 직후 LLM 이 "규정에서 확인되지 않는다. 다만 …(정답)" 식으로 과하게 거절 (W2 에서 강화한 거절 규칙의 부작용)
  → "인용문으로 결론을 낼 수 있으면 답한다" 로 규칙을 바꿔 4건 → 2건.
- 남은 LLM 오거절 2건은 **모델의 한 단계 추론 실패**: q009 "직원이었던 자" = 퇴직자, q015 배분 + 실적 분석 의무.

**실험: Qwen3 thinking 모드** (오거절 · 거절 민감 문항 8개)

| | thinking 끔 | thinking 켬 |
|---|---|---|
| answerable 판단 | 6/8 | 8/8 |
| 생성 시간 | 2.6~7.6s | 7.1~14.0s |
| 내용 | - | q015 를 "네, 의무를 다한 것" 으로 **결론을 뒤집음** |

→ 기본값으로 채택하지 않음 (지연 2~3배, 새 오답). 거절 문항 4개 · 33문항 기준이라 프롬프트를 더 맞추면 과적합 위험 → Golden Set 확장 후 재평가.

**남은 과제**: 오거절 2건(모델 추론) · p95 지연 10.4s(인용문 출력 증가 — 인용 개수 · 길이 상한 축소 검토) · q001 인용이 별표1 대신 제16조

### 3. 하이브리드 검색 (2026-10-22, Golden Set 43문항 · refuse 제외)

| 방식 | R@1 | R@3 | R@5 | MRR | 검색 p50 |
|---|---|---|---|---|---|
| dense (W2) | 0.74 | 0.95 | 0.95 | 0.848 | 24ms |
| BM25 (Kiwi) | **0.88** | 0.95 | 0.95 | **0.926** | 20ms |
| **hybrid (RRF)** | 0.79 | **0.98** | **1.00** | 0.881 | 28ms |

리포트: [dense](../eval/reports/w3_retrieval_dense.md) · [bm25](../eval/reports/w3_retrieval_bm25.md) · [hybrid](../eval/reports/w3_retrieval_hybrid.md)

**방법** — BM25 는 Kiwi 형태소 분석(조사 제거, 명사 · 어간 · 숫자) + 연속 명사 결합("강사"+"료" → "강사료"). dense · BM25 각 30개를 RRF(k=60)로 합친다.
BM25 로만 찾은 청크도 dense 코사인을 계산해 붙여, 검색 단계 거절 기준(0.45)이 모든 결과에 같은 척도로 적용되게 했다.

**해석**
- BM25 단독이 1위 적중 · MRR 최고 — 단, Golden Set 질문을 원문을 보며 써서 **원문 단어가 질문에 들어 있는 편향**이 있다.
- 답변 단계는 상위 8개를 근거 후보로 쓰므로 **R@5 가 핵심** → hybrid 가 유일하게 1.00. 기본값을 hybrid 로 바꿨다 (`SEARCH_MODE`).
- 원문과 다른 표현으로 쓴 확인용 질문 6개(Golden Set 아님): hybrid 가 5개를 2위 안에서 찾음.
  "강의하러 가서 받을 수 있는 돈 상한은?" dense 2위 → hybrid 1위, "회사 차 타고…" BM25 6위 → hybrid 2위.
- **세 방식 모두 실패**: "그만둔 다음에 회사 일 얘기해도 돼?" (정답 취업규정 제5조 "직원이었던 자 … 직무상 알게 된 사항을 누설") —
  겹치는 단어가 없어 상위 30개 밖. 리랭커는 후보 안에서만 순서를 바꾸므로 못 푼다 → **작업 7 쿼리 재작성** 추가.
- 답변 평가(`eval.answer`)는 Golden Set 정리(refuse 오분류 4건) 후 hybrid 로 다시 잰다.

### 7. 쿼리 확장 — 일상어 질문 (2026-10-22, Golden Set 100문항 중 답변 가능 85)

**문제**: "그만둔 다음에 회사 일 얘기해도 돼?" (정답 취업규정 제5조 "직원이었던 자 … 직무상 알게 된 사항을 누설")는
겹치는 단어가 없어 dense · BM25 · hybrid 모두 상위 30개 밖.

**시도 1 — LLM 쿼리 재작성 (Qwen3 8B, 해석 2~3개 + 가상 조문)**: ❌ 채택 안 함
- 목표 질문: 해석 3개가 모두 "퇴직 후 업무 참여"로 빗나가 여전히 8위 밖 (모델이 "얘기하다 = 누설" 연결을 못 함)
- 첫 시도는 "규정과 무관"으로 판단해 빈 결과 → 범위 판단은 뒤 단계에 맡기도록 규칙 수정
- 점수가 높은 질문에도 적용하면 결과를 흐림 ("회사 차 타고…" 2위 → 7위), 호출당 +3~4초, 가상 조문에 지어낸 숫자
- Golden 85문항 (기준 0.62 미만일 때만 재작성): R@5 1.00 → 0.99, p95 36ms → 4,048ms
- 코드는 남기고 기본값 끔 (`--rewrite auto|always` 로 실험 가능) — 더 큰 모델에서 재실험 여지

**시도 2 — 일상어 → 규정 용어 사전 (`data/glossary.csv`, 37개 항목)**: ✅ 기본 켬
- 사전은 평가 질문이 아니라 일반적인 직장 구어 표현으로 작성, 확장 용어가 실제 원문에 있는지 테스트로 검사
- 사전에 걸리면 "원래 질문 + 규정 용어"로 dense · BM25 검색 (원래 질문 검색을 함께 섞으면 효과가 희석: 목표 질문 8위 → 1위)

| Golden 85문항 | R@1 | R@3 | R@5 | MRR | 검색 p95 |
|---|---|---|---|---|---|
| hybrid (사전 없음) | 0.88 | 0.99 | 1.00 | 0.934 | 36ms |
| **hybrid + 사전** | **0.92** | 0.99 | 1.00 | **0.953** | 100ms |
| hybrid + 사전 + LLM 재작성(auto) | 0.91 | 0.96 | 0.99 | 0.942 | 4,048ms |

리포트: [사전 없음](../eval/reports/w3_7_hybrid_no_glossary.md) · [사전](../eval/reports/w3_7_hybrid_glossary.md) · [사전+재작성](../eval/reports/w3_7_hybrid_glossary_rewrite.md)

- 사전이 85문항 중 28문항에서 작동, 떨어진 문항 없이 R@1 +0.04
- **한계**: 사전 효과의 공식 검증은 사람이 쓴 일상어 문항(notes 에 "일상어")으로 해야 한다 — 아직 0문항.
  위 확인용 일상어 질문 6개는 사전을 만든 쪽이 쓴 것이라 근거로 삼지 않는다.

### 8. Golden Set 확장 후 재측정 (2026-10-22, 110문항: fact 55 · numeric 22 · multi 16 · refuse 17 · 일상어 20)

Golden Set 정리: refuse 오분류 8건 재분류("안 됩니다"도 근거가 있으면 fact), 진짜 refuse 10문항 추가(원문 검색으로 부재 확인),
사람이 쓴 일상어 문항 20개(notes "일상어"). 남은 확인 사항: q104(refuse 이지만 인사규정 제74조로 답 가능, q037 과 중복),
q037 · q055 답 칸이 아직 "답변할 수 없습니다".

**검색** — 일상어 사전 결합 방식을 사람이 쓴 일상어 문항으로 공식 검증

| | 전체 93 MRR | 일상어 16: R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|---|
| dense | 0.869 | **0.50** | 0.81 | 0.88 | **0.636** |
| hybrid (사전 없음) | 0.878 | 0.44 | 0.81 | 0.94 | 0.582 |
| hybrid + 사전 (확장 검색만, 7단계 기본값) | 0.888 | 0.38 | 0.88 | 0.88 | 0.568 |
| **hybrid + 사전 (원래 + 확장, add)** ← 채택 | **0.894** | 0.44 | **0.88** | 0.88 | 0.599 |

- 7단계의 "확장 검색만" 방식은 사전이 빗나가면 원래 결과를 잃었다: q081 "교통비"→운임 확장으로 6위 → 10위 밖 → **add 로 변경**
- 일반 동사 패턴("알려" → 누설, q065 오작동) 제거는 효과가 없어 하지 않음 (평가 문항을 보고 사전을 고치는 것을 최소화)
- 일상어에서는 dense 단독이 R@1 최고 — 단어가 다르면 BM25 가 방해. 사전에 없는 표현("복지 포인트", "회사에 넣은 요청")은
  평가 문항을 보고 추가하지 않는다 → 실사용 로그로 보강할 과제
- 16문항이라 1문항 = 6%p — 방향은 보이지만 단정하기엔 작다
